Reports Kotlin code that runs on a background thread and reaches a blocking, non-cancellable read action.

A background entry point is a Task.Backgroundable run(ProgressIndicator) override, a function annotated @RequiresBackgroundThread, or a task passed to executeOnPooledThread, AppExecutorUtil's executors or runBackgroundableTask. The blocking calls are ReadAction.compute()/run()/computeBlocking()/runBlocking(), runReadAction {}, runReadActionBlocking {}, DumbService#runReadActionInSmartMode(...) and Application#runReadAction(...).

While such a read action runs, a pending write action waits for it, and write actions usually run on the UI thread: the IDE freezes. Use ReadAction.nonBlocking(...).executeSynchronously() or readAction {} instead. A non-blocking read action restarts when a write action comes, so keep side effects (writing files, scheduling UI work) outside of it.

Calls are followed into functions of the same file only. Code inside invokeLater, write actions, ReadAction.nonBlocking or readAction {} is not reported.
