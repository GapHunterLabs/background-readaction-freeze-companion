Reports a background-thread entry point (a Task.Backgroundable override, a method annotated @RequiresBackgroundThread, a task passed to Application#executeOnPooledThread, to the AppExecutorUtil pooled executor, or to BackgroundTaskUtil#executeOnPooledThread) that can reach a blocking, non-cancellable read action, directly or through a project method.

A blocking read action on a background thread makes pending write actions wait, which can freeze the editor. Reported calls: ReadAction.compute()/run() (deprecated), ReadAction.computeBlocking()/runBlocking() (their documentation says "Avoid usage in background threads"), DumbService#runReadActionInSmartMode(...), and Application#runReadAction(...), whose documentation advises against this use. A non-blocking read action (ReadAction.nonBlocking(...)) yields to writes and follows cancellation. It restarts when a write action comes, so keep side effects outside of it.
